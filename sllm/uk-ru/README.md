Ассистент по проблемам в многоквартирном доме: определяет, отвечает ли за проблему управляющая компания, и — если да — выдаёт готовый шаблон заявления в УК.

Работает **без единого аккаунта и API-ключа**: модель локальная через [Ollama](https://ollama.com), нормы ищутся в локальном собрании НПА, а если его не хватает — в своём же контейнере с метапоисковиком [SearXNG](https://docs.searxng.org), который поднимается по требованию и гасится за собой.

> ⚠️ Это не юридическая консультация. Проверка цитат гарантирует, что норма **существует** и процитирована верно, но не то, что она **уместна**: модель может подобрать подлинную, однако не относящуюся к делу норму. Выводы перед использованием нужно перепроверять.

## Как это работает

**Фаза 1 — корпус.** Агенты получают только `corpus_search` и `corpus_get`. Веб-инструментов у них нет физически, уйти в интернет неоткуда.

Перед запуском агентов скрипт сам ищет по корпусу **словами пользователя** и кладёт находки им в контекст. Без этого модель первым делом переводит бытовое описание на юридический язык — «доводчик» превращается в «запирающие устройства» — и находит общий пункт вместо профильного, хотя в акте написано именно «доводчики».

**Текст нормы берётся из корпуса, а не от модели.** Сначала по номеру ищется сам пункт: нашёлся — цитатой становится текст из корпуса. Требовать побуквенного копирования от небольшой модели бессмысленно: норму она выбирает уверенно, а формулировку пересказывает, и строгая проверка теряла правильно найденные пункты. Если присланная цитата совпала с текстом пункта — используется она, иначе подставляется первое предложение пункта, а замена пишется в лог.

Пункт не опознан — цитата ищется по всему корпусу; не нашлась и там — норма отбрасывается. Совпадение считается по нормализованной форме (регистр, пробелы, ё/е содержания не меняют), при неполном совпадении подтвердиться должно не менее 60% присланного (`PARTIAL_RATIO`), и в ответ уходит только подтверждённая часть.

Итог: сослаться на несуществующий пункт или процитировать по памяти нельзя — до пользователя доходит только текст, который есть в акте.

**Фаза 2 — веб, только если понадобилось.** Если у агента не осталось ни одной подтверждённой нормы, он идёт в интернет — и вот тогда поднимается докер с SearXNG. Хватило корпуса всем — докер не трогается вовсе.

Цитаты из веба проверяются по тексту страниц, которые агенты **реально открыли**, а не по ссылке из ответа. Это не педантизм: модель, которой в промпте велено предпочитать официальные источники, охотно читает справочник, а в ответе подставляет ссылку на `pravo.gov.ru` — проверка по её ссылке отбрасывала бы добросовестные нормы и пропускала выдуманные. В ответ уходит тот адрес, где цитата действительно нашлась, а подмена пишется в лог.

**Консенсус.** Побеждает вердикт большинства (порог по умолчанию — большинство от числа агентов). В ответ попадают только нормы, независимо найденные не менее чем `MIN_CONSENSUS` агентами. Голос агента без единой подтверждённой нормы не учитывается вообще: иначе «я ничего не нашёл» весит столько же, сколько разобранная позиция со ссылками.

**Финальный ответ** собирается отдельным вызовом строго из согласованных норм — добавлять новые ссылки модели запрещено, называть сроки и суммы, которых нет в цитатах, тоже. После этого модель выгружается из памяти (`keep_alive=0`).

## Корпус

Тексты лежат в `corpus/*.txt`, метаданные (источник, редакция, размер, хеш) — в `corpus/index.json`. Корпус коммитится в репозиторий: смена редакции видна в дифе и не происходит внезапно посреди работы.

| Акт | Источник |
|---|---|
| Жилищный кодекс РФ | pravo.gov.ru |
| ПП 491 — содержание общего имущества | pravo.gov.ru |
| ПП 290 — минимальный перечень работ и услуг | pravo.gov.ru |
| ПП 354 — предоставление коммунальных услуг | pravo.gov.ru |
| ПП 416 — деятельность по управлению МКД | pravo.gov.ru |
| ФЗ-59 — порядок рассмотрения обращений граждан | pravo.gov.ru |
| КоАП РФ, ст. 7.22–7.23 | pravo.gov.ru |
| Правила и нормы технической эксплуатации жилфонда (Госстрой 170) | зеркало sudact.ru |

Обновление — отдельной командой, не при каждом запуске:

```bash
python3 corpus_update.py            # всё
python3 corpus_update.py --only zhk-rf
python3 corpus_update.py --list     # что откуда взято и когда
```

Загрузчик сам находит номер действующей редакции в карточке акта и проверяет скачанный текст по контрольному маркеру: если идентификатор протух и приехал чужой документ, акт не сохранится, а не попадёт в корпус молча.

Госстрой 170 остался на зеркале: его ND в официальной ИПС найти не удалось (поиск там работает только через JS, а ND — порядковый номер ввода в систему, из даты и номера акта не выводится). Если найдёте — впишите `"nd"` в реестр `ACTS`, и акт переедет на официальный источник автоматически.

## Требования

- Python 3, `pip install requests trafilatura rank_bm25`
- [Ollama](https://ollama.com) и модель с поддержкой инструментов:
  ```bash
  brew install ollama            # macOS; см. ollama.com/download для других ОС
  ollama pull qwen3.5:9b         # ~6.6 ГБ
  ```
- Docker — **только для веб-фазы**. Подойдёт OrbStack, Docker Desktop или colima; если не запущен, скрипт запустит его сам. Нет докера — веб-фаза просто отключится, корпус продолжит работать.

Три агента с контекстом 16k на 9B-модели укладываются примерно в 18 ГБ единой памяти. Если не хватает — уменьшайте `SLLM_AGENTS` и `SLLM_NUM_CTX` либо берите модель меньше.

## Использование

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install requests trafilatura rank_bm25

python3 corpus_update.py        # один раз собрать корпус
python3 uk-ru.py "Входная дверь в подъезд не закрывается, домофон не держит замок"
```

Ход работы идёт в stderr, результат — в stdout, так что ответ можно перенаправить:

```bash
python3 uk-ru.py "В квартире всю зиму 16 градусов" > ответ.md
```

Хотите гарантированно офлайн, без шанса поднять докер — `SLLM_WEB=0`.

## Настройка

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SLLM_MODEL` | `qwen3.5:9b` | модель Ollama; нужна поддержка вызова инструментов |
| `SLLM_AGENTS` | `3` | сколько независимых агентов запускать |
| `SLLM_MIN_CONSENSUS` | большинство от `SLLM_AGENTS` | порог согласия для вердикта и для попадания нормы в ответ |
| `SLLM_NUM_CTX` | `16384` | размер контекста |
| `SLLM_WEB` | `1` | `0` полностью запрещает веб-фазу и запуск докера |
| `SLLM_FORCE_WEB` | `0` | `1` пропускает корпус и идёт сразу в веб — для проверки, что докер поднимается |
| `SLLM_THINK` | `0` | режим размышлений модели, по умолчанию выключен (см. ниже) |
| `SLLM_DEBUG` | `0` | печатать расход контекста на каждый запрос |
| `SLLM_OLLAMA_HOST` | `http://127.0.0.1:11434` | адрес сервера Ollama |
| `SLLM_SEARX_PORT` | `18080` | порт локального SearXNG |
| `SLLM_SEARX_IMAGE` | `searxng/searxng:latest` | образ метапоисковика |

Порог по умолчанию — `SLLM_AGENTS // 2 + 1`: при трёх агентах 2, при пяти 3. Задавать явно имеет смысл только в сторону ужесточения: значение вполовину агентов и меньше пропускает вердикт без реального большинства, а равное их числу требует единогласия и не оставляет допуска ни на одно падение.

`SLLM_THINK=0` добавляет в запрос `"think": false`. Без этого thinking-модели (в том числе `qwen3.5`) кладут ответ в поле `thinking`, оставляя `content` пустым, и структурированный вывод перестаёт парситься. Если модель не понимает параметр, скрипт повторит запрос без него.

Остальное правится константами в начале файлов: `MAX_TOOL_ROUNDS`, `HISTORY_KEEP_FULL` (сколько последних ответов инструментов хранятся целиком) в `uk-ru.py`, `CHUNK_CHARS` и `MIN_QUOTE_CHARS` в `corpus.py`, таймауты и порт в `runtime.py`.

## Что откуда

| Файл | Отвечает за |
|---|---|
| `uk-ru.py` | оркестрация фаз, консенсус, финальный ответ |
| `corpus.py` | нарезка актов, BM25-поиск, верификация цитат |
| `corpus_update.py` | загрузка текстов НПА, реестр актов |
| `runtime.py` | подъём и уборка докера и контейнера SearXNG |
| `websearch.py` | поиск через SearXNG, загрузка страниц |
| `corpus/` | тексты актов и `index.json` |

## Докер: что именно поднимается и гасится

- Контейнер SearXNG стартует **только** в веб-фазе и останавливается всегда.
- Если docker-демон не отвечал, скрипт запускает OrbStack / Docker Desktop / colima — что найдёт первым.
- Гасит рантайм только при двух условиях сразу: **он же его и поднял** и после остановки своего контейнера **не осталось чужих**. Контейнеры с `restart: always` стартуют вместе с демоном, и гасить его вслепую значит убить чужую работу — в этом случае в лог пишется, почему рантайм оставлен.
- Уже запущенный чужой SearXNG на том же имени контейнера переиспользуется и не останавливается.

## Диагностика

| Сообщение | Что делать |
|---|---|
| `Корпус не собран` | запустите `python3 corpus_update.py` |
| `Не установлена модель ...` | `ollama pull` с указанным именем |
| `норма отброшена: цитаты нет в корпусе дословно` | штатная работа фильтра — модель пересказала норму вместо цитирования |
| `Норм с подтверждёнными цитатами хватило только у N агентов` | нужного акта нет в корпусе — добавьте его в `ACTS` или разрешите веб-фазу |
| `Агенты не сошлись во мнении` | ситуация пограничная: переформулируйте конкретнее или запустите повторно |
| `[agent N] сбой: модель вернула пустой ответ` | модель не отдала structured output; проверьте поддержку `format` и `SLLM_THINK=0` |
| `[agent N] сбой: Unterminated string ...` | контекст кончился до конца JSON; скрипт делает автоповтор с ужатой историей, дальше — снижайте `MAX_TOOL_ROUNDS` или поднимайте `SLLM_NUM_CTX` |
| `docker недоступен` | ни один рантайм не запустился; корпус продолжит работать без веба |
