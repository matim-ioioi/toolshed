**Сарай с инструментами.** Монорепозиторий с разношёрстными утилитами и приложениями — от маленьких CLI-скриптов до полноценных приложений под конкретные задачи. Каждый инструмент самодостаточен: живёт в своей папке, имеет свою инструкцию по запуску и не тянет за собой остальные.

Здесь нет единой темы. Есть общий принцип: если что-то оказалось полезным и переиспользуемым — оно едет сюда, в свой отсек, а не теряется по десятку разрозненных репозиториев.

## Структура

Инструменты сгруппированы по областям. Каждая папка верхнего уровня — это отдельная «полка»:

| Полка                  | О чём                                                                 |
|------------------------|-----------------------------------------------------------------------|
| [`claudex/`](#claudex) | Утилиты и приложения для тех, кто работает с Claude Code              |
| [`utils/`](#utils)     | Разные утилиты общего назначения, не привязанные к конкретной области |

Список пополняется — новые полки заводятся по мере появления инструментов из новых областей.

## claudex

Инструментарий вокруг Claude Code: то, что делает повседневную работу с агентом удобнее, чище и предсказуемее.

### `wipe-claude-project-memory.py`

Полное удаление всех данных, которые Claude Code накапливает о проекте, — чтобы «обнулить» его знания о конкретной кодовой базе.

Скрипт сканирует `~/.claude` и `~/.claude.json`, показывает таблицу известных проектов с объёмом накопленных данных, даёт выбрать нужные и вычищает всё, что Claude Code о них хранит:

- транскрипты сессий, история промптов, запись о проекте в конфиге и её бэкапы;
- снапшоты правок, окружение сессий, todo / task / job / debug и прочие служебные файлы;
- временные файлы во `/private/tmp`.

**Файлы внутри самого проекта не трогаются** — ни рабочий код, ни `.claude/` внутри проекта (settings, agents, commands, worktrees). Это гарантируется не только логикой обхода, но и защитой в самой функции удаления: любой путь внутри каталога проекта или вне белого списка каталогов с данными Claude Code отбрасывается. Пользовательские настройки и глобальная память (`~/.claude/CLAUDE.md`, `settings.json` и т.п.) тоже в списке защищённых.

Дополнительно: предупреждает, если в выбранном проекте прямо сейчас запущена сессия Claude Code (иначе она допишет свои данные при выходе), и умеет проверять, не осталось ли остаточных упоминаний.

```bash
./wipe-claude-project-memory.py                       # интерактивный выбор
./wipe-claude-project-memory.py --dry-run             # показать план, ничего не удалять
./wipe-claude-project-memory.py --all --yes           # снести всё без вопросов
./wipe-claude-project-memory.py --project /path/to/proj [--project ...]
```

Только стандартная библиотека Python 3 — зависимостей нет.

## utils

Утилиты общего назначения: то, что не относится ни к одной конкретной области.

### `privacy_anonymizer_ru.py`

Обезличивание русскоязычных документов — маскирование персональных данных (ориентировано на РФ-сегмент). Работает в два независимых слоя, каждый включается отдельным флагом:

1. **REGEX-слой** — чистый Python, детерминированно. Документные ПД, которые выводятся по формулам и регуляркам: ИНН, СНИЛС, паспорт РФ, банковская карта, телефон, email. Номера с контрольной суммой (ИНН / СНИЛС / карта по Луну) проверяются — случайные совпадения цифр не маскируются.
2. **LLM-слой** — смысловые ПД, которые нельзя вывести скриптом: имена людей, организации, локации, адреса, логины. Локальная маленькая модель через [Ollama](https://ollama.com) поднимается, возвращает спаны в JSON и сразу выгружается из памяти. **Модель ничего не переписывает** — только находит; сама замена делается детерминированно в коде.

Всё считается **локально, на машине пользователя. Никакие данные никуда не утекают, и это бесплатно.** Структурные regex-ПД имеют приоритет над догадками модели; из ответа LLM принимаются только строки, дословно встречающиеся в исходном тексте (защита от галлюцинаций). Ссылки по желанию либо маскируются целиком как `<URL>`, либо, наоборот, защищаются от изменений.

**Требования:** Python 3, `pip install requests`, установленный Ollama и модель (`ollama pull qwen3:4b`, ~2.5 ГБ). Если Ollama или модель недоступны — скрипт не падает, а работает только regex-слоем, предупредив об этом.

```bash
python -m venv .venv && source .venv/bin/activate
pip install requests

# в файл
python utils/privacy_anonymizer_ru.py входной.txt выходной.txt
# или в stdout, если второй аргумент не задан
python utils/privacy_anonymizer_ru.py входной.txt
```

Слои, категории LLM, модель и поведение со ссылками настраиваются в блоке `КОНФИГ` в начале файла.

## Как это устроено

- Каждый инструмент самодостаточен и документирует свой запуск сам (в docstring / README).
- Новый инструмент едет в подходящую существующую полку; для новой области — заводится новая папка верхнего уровня.
